## 二、怎么研究这个网站

**能做的**：用你可用的浏览器工具实际打开、游玩、截图、计时、读页面文字、看网络请求的文件类型和大小，观察和测量。
**不能做的**：不要下载、解包、反编译它的 WebGL 构建、模型、贴图、着色器或代码，不要把它的任何素材或文字放进我们的项目。我们学的是手法和标准，不是素材。它的截图只能存在 `art/design/v2/benchmark/reference/` 里做内部比对，不能进游戏或宣传材料。

**已知的操作方法**（Claude 实测）：
- 用 Chrome 或 Edge，**真实的横屏窗口，至少 1440×900**。在缩放模拟出来的视口里，点击和键盘可能不进游戏。
- 首页点“点击 · 开始旅程” → Unity 加载 → 羊皮纸“小王子的旅程”章节地图 → 点第一颗星球选中 → 按 Enter 进入 → 全屏星空章节标题卡 → 第一章实机（B-612，黄昏，草地，左上角出现任务提示）。
- 如果你无法实际操作游戏，就如实说明卡在哪一步，并请用户提供录屏或截图，**不要凭想象写观察结果**。

**研究方法**：
- 每个画面都按固定节奏截图（例如开场后第 0、1、2、4、8 秒），用来测量淡入淡出、镜头推进和文字出现的时长。
- 在同样的分辨率下，把我们的游戏（`Assets/JieGuang/Scenes/JieGuang_Main.unity`）对应画面也截下来，做**同类画面并排对比**：标题、章节地图或选关、章节标题卡、第一次进入可操作画面、走路、对话、任务提示、解谜界面、过场、结尾。
- 在 1440×900 下记录它的帧率感受和加载时间；记录它首屏加载了哪些类型的文件、多大（只看大小和类型，不下载内容）。

## 三、拆解报告要覆盖的方面（每一项都写成“它怎么做 → 我们现在怎样 → 差距 → 具体做法，写到参数级别”）

1. **构图与镜头**：机位高度、视角（估算 FOV）、人物在画面中的位置和大小、跟随延迟与阻尼、转场镜头怎么推拉摇、开场镜头怎么引出人物、有没有固定机位。
2. **光照**：时段和色温，主光、补光、轮廓光的方向和颜色，阴影软硬，环境光的颜色倾向，人物脸部怎么打亮。
3. **后期处理**：色调映射、调色倾向（暖/冷、对比度、饱和度）、泛光的强度和范围、景深（前景/背景虚化的程度）、暗角、胶片颗粒、雾。
4. **天空与远景**：天空渐变、云（体积感、云海）、远景层次、空气透视。
5. **植被与地面**：草的密度、高度变化、种类、颜色变化、风动幅度和频率，野花的种类和分布规律，石头和小路怎么嵌进草地，地面贴图的细节层次。
6. **模型与材质**：建筑、道具、人物的材质精度，边角磨损、颜色饱和度、光滑度，模型轮廓风格。
7. **人物与动画**：步行速度和步态、待机动作、转身是否平滑、脚是否贴地、有没有呼吸、头发和围巾的摆动。
8. **UI 视觉**：所有出现过的界面元素，字体风格、字号（按 1080p 换算像素）、字距、行距、颜色值（估取 RGB）、位置、留白、图标风格、有没有背板、阴影或描边。
9. **UI 动效与节奏**：标题卡、任务提示、对话、过渡各自的淡入淡出时长，文字出现方式（逐字、整句、渐显），停留多久。
10. **交互手感**：移动响应、加速减速、相机控制方式（鼠标或键盘）、任务如何指引（文字、光点、镜头引导）、可交互物怎么提示、对话怎么推进、有没有声音反馈。
11. **音频**：音乐风格和配器、环境声（风、草、海、鸟）、交互音效、音量层次、章节切换时音乐怎么过渡。
12. **叙事节奏**：章节怎么开场，第一句话在第几秒出现，玩家多久后拿到控制权，信息量多大。
13. **加载与性能**：首屏和章节加载时长、加载画面的设计、帧率表现、包体量级。

报告最后给出一张**按投入产出排序的改进清单**，每项标注：负责人（你 / Claude / 用户用 Tripo 生成）、预计改动的文件或资产、验收标准（用哪张对比截图判断“追平了”）。
